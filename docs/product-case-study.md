# 产品案例：把原料机会研究变成可验证的决策工作流

## 1. 场景与用户

### 首要用户假设

- **首要用户：原料业务负责人。** 需要决定继续研究、做样品、发 RFQ、进入中试还是停止；
- **协作者—销售：** 判断先推哪个应用、联系哪些账户、谈什么价值；
- **协作者—应用研发：** 明确起始用量、对照和否决方向的结果；
- **协作者—市场/战略：** 区分市场空间、可服务需求和当前可成交需求。

这些角色和任务来自案例审计与工作流假设，尚未通过真实用户访谈、使用频率、现有替代流程或采用阻力数据验证。

### Job to be done

当一个原料有论文、法规、供应商材料和零散市场信号时，团队需要在有限时间内形成一个可追溯的下一步判断，同时知道哪些结论还不能说。

## 2. 问题不是“缺报告”，而是证据层级混乱

一次典型研究同时包含分子特性、成品表现、法规许可、产品标签、零售数据、市场报告、供应商披露和客户线索。它们回答的问题不同，却很容易被模型压缩成同一个“机会结论”。

关键风险是：

1. **对象错误：** 同名原料、牌号、来源、菌株或活性含量不一致；
2. **因果越界：** 机制、动物、专利、标签和销量被写成成品人体功效；
3. **市场错配：** 产能、生产、库存、销售、需求和市场价值混为一谈；
4. **客户幻觉：** 品类匹配被写成正在使用、采购或有决策权；
5. **行动无效：** 报告给出宏观建议，却没有实验、询价、标签核验或停止条件。

## 3. 产品目标与非目标

### 目标

- 降低错误商业推进的概率；
- 把每个候选应用追溯到原料特性、产品问题和硬门槛；
- 把未知项转化为最小、可执行、能改变决定的验证动作；
- 让不同 Agent、研究员和评审可以复查同一证据边界。

### 非目标

- 自动替专家决定市场是否值得进入；
- 用一个机会分数代替法规、技术、需求与客户判断；
- 从公开资料推断保密配方、供应商或采购意向；
- 用更长、更像咨询报告的文字掩盖证据缺口。

## 4. 从用户决策反推产品需求

| 用户决定 | 必须回答 | 产品机制 |
|---|---|---|
| 是否继续研究 | 身份、可支持特性、核心风险 | 身份规范化、逐行原始证据、失败模式 |
| 先做哪个应用 | 产品问题、法规、技术、用量、成本 | property-to-need 链与硬门槛 |
| 做什么产品 | 具体基质、工艺、包装、接触方式和宣称 | product-format screening |
| 市场是否真实 | 需求成熟度、合格供应和口径对齐 | 三视角市场审计与供需三轴 |
| 找谁谈 | 当前采用、替代体系、项目和购买信号 | SKU 级采用分类与账户证据 |
| 下一步花什么钱 | 哪项未知最可能改变结论 | 最小实验、RFQ、法规核验和停止条件 |

## 5. 关键产品取舍

### 取舍一：硬门槛优先于完整度

身份或核心法规错误时，即使报告覆盖很多市场数据也不能进入决策。系统先检查硬门槛，再评研究质量。

### 取舍二：不同状态不压成一个分数

`advance`、`conditional—experiment required`、`regulatory unresolved`、`technical evidence insufficient` 和 `do not advance` 分别对应不同下一步。供需判断也分开表达需求成熟度、供应约束和证据状态。

### 取舍三：渐进加载，而不是把所有规则塞进主提示词

`SKILL.md` 只负责路由和核心流程；法规、价格、技术、市场、客户、语言与质量规则按任务加载。这样减少无关上下文，同时让复杂模块可独立修复。

### 取舍四：负面结论也是交付

当数据不能对齐时，输出 `not reliably estimable`；当客户只有品类匹配时，输出 `exploratory lead`；当具体牌号或法规未闭环时，不作商业推进结论。

## 6. 验证策略

### 层 1：结构

检查文件、frontmatter、相对链接、必需 references 和案例基本章节。这是最低门槛，不证明内容正确。

### 层 2：行为

用有明确失败条件的对抗场景检查：是否混淆身份、转移法规、虚构采用、错误归因、错误计算供需缺口。

### 层 3：案例

对不同复杂度的真实公开资料案例做硬门槛和统一质量量表审计。评分衡量报告质量，不衡量原料机会，也不自动证明 Skill 的因果贡献。

### 层 4：受控对照

冻结输入、任务、截止日期、工具权限和输出限制，分别运行 Skill 与无 Skill 组，再由不知道分组的评审按预注册量表评分。单个合成场景只用于发现行为差异，不能替代多案例、多人和真实工作流验证。

### 层 5：业务效用

未来需要记录专家修改量、完成时间、阻塞项发现率、错误商业结论率，以及报告是否改变了实验、RFQ、客户或停止决定。当前尚无这层证据。

## 7. 成功指标

| 指标 | 下一轮预注册门槛 | 当前状态 |
|---|---|---|
| 关键硬门槛漏检 | 5 个真实冻结案例中为 0，且不得差于无 Skill 基线 | 单个合成对照中两组均为 0，样本不足 |
| 无证据强结论 | 3 名盲评者一致认定的严重越界为 0 | 规则和硬失败项已定义，尚无人类盲评 |
| 决策 blocker 召回 | 相对专家共识清单至少 90% | 四个案例保留 blocker，但无专家 gold set |
| 下一步可执行性 | 盲评中至少 4/5 案例给出对象、动作、证据和停止条件 | 合成案例满足，真实案例未统一测量 |
| 专家修改时间 | 中位数较无 Skill 基线减少至少 20% | 未测 |
| 专家实质修改量 | 中位数较无 Skill 基线减少至少 15% | 未测 |
| 停止条件 | 若 5 个案例中任一出现 Skill 独有硬失败，或未达到至少 4/5 的可执行性门槛，则不声称改进并继续修复 | 尚未触发真实验证 |

## 8. 当前结论

这个项目已证明的是：复杂原料研究可以被拆成可检查的决策链，案例中的未知可以被明确保留，结构和行为可以被重复验证。

它尚未证明的是：相对其他研究方式在大样本上更准确、更快，或能提高真实销售、立项和投资回报。下一阶段应优先补真实专家基线和多案例盲评，而不是继续增加规则数量。
