# Iteration log

本记录只把有可观察问题、明确假设、具体修改和验证结果的变化称为迭代。措辞和排版改善单独标为 presentation，不冒充证据改善。

## Iteration 1：从应用清单转为特性—需求链

- **问题信号：** 通用研究容易先列热门品类，再倒推原料卖点。
- **假设：** 强制每个应用从可引用的原料特性出发，可以减少无依据的机会列表。
- **最小修改：** 增加 `property → product problem → required function → application`，无直接证据时必须标 hypothesis。
- **验证：** Isomalt、Gellan gum、HMO 三个案例逐项检查身份和应用追溯。
- **结果：** 保留。它提高可审计性，但没有单独证明商业预测更准确。

## Iteration 2：把公司相关性与当前采用分开

- **问题信号：** 公司生产某类产品，经常被误写成正在使用目标原料。
- **假设：** 只有市场、SKU、日期和完整标签可定位时，才允许记为 current use。
- **最小修改：** 增加 `verified current use / development evidence / possible use / no public evidence found / confirmed absent`，并披露公司、SKU、渠道和标签覆盖。
- **验证：** 三个历史案例重新审计；无法取得完整标签时降级，而不是写成非用户。
- **结果：** 保留。案例中的客户结论更保守，剩余缺口仍公开。

## Iteration 3：Bisabolol 暴露产品形态和市场口径问题

- **问题信号：** “舒缓护肤”不能回答先做面霜、精华、水剂还是洗去型产品；供应商的 500–800 吨需求说法缺少独立闭环。
- **假设：** 产品形态筛选和供给/贸易/下游三视角会阻止从大类 GMV 直接推原料需求。
- **最小修改：** 新增 `product-format-screening.md` 与 `market-size-and-demand.md`，要求基质、工艺、接触方式、用量、宣称、替代品、SKU、买家和决定性缺口。
- **验证：** Bisabolol 案例逐形态输出标准结果；全球及中国原料需求被标为不可可靠估计；验证脚本检查必要结构。
- **结果：** 保留。结构验证通过，但案例仍是 pre-audit，不因新增章节获得质量分。

## Iteration 4：修复“数字相近就是交叉验证”

- **问题信号：** 供应商产量估计和二手市场价值可能来自同一来源，算术相容不等于独立佐证。
- **假设：** 在比较数值前显式检查来源独立性和对象、规格、地区、期间、价值链层级，可以降低伪交叉验证。
- **最小修改：** 在 evidence rules 中要求追溯最早来源；把生产路线、纯度、规模、产能、客户认证、订单、销售和财务贡献拆成独立 claim。
- **验证：** Nootkatone 场景和测试用例不得让一个公司披露确认整条商业链。
- **结果：** 保留；仍需要跨案例盲评量化改善。

## Iteration 5：修复供需缺口和扩产推断

- **问题信号：** 推荐摄入差、低渗透率、跨市场预测、非约束询盘和 nameplate capacity 被直接相减。
- **假设：** 分开 demand maturity、supply constraint 和 evidence status，并要求口径对齐，可以阻止虚假精度。
- **最小修改：** 新增供需 gap audit、非重叠公式、标准结论和六个对抗断言；增加 standalone financial materiality 与 platform value 边界。
- **验证：** `test-scenarios.md` 中的对抗断言，以及 `controlled-test/` 的冻结输入对照。
- **结果：** 受控对照中，无 Skill 组 96/100，Skill 组 99/100，两组均无硬失败。差异集中在价格口径与扩产触发条件；结论仅适用于这个合成场景，不能外推为业务效果。

## Iteration 6：修复“价格不可比”过于抽象

- **问题信号：** 第一轮盲审发现 Skill 组只写“价格不可比”，没有逐项说明比较为何失败。
- **假设：** 要求在商业或资本决策中点名决定性的错配字段，会提高审计性而不增加虚假精度。
- **最小修改：** 在 `price-research.md` 增加一条：列出活性规格、数量、日期、币种、税费、运费/Incoterms、付款条件和供应商类型，并给出最小同口径 RFQ/成交证据。
- **验证：** 使用同一冻结输入复测；第二轮盲审将修复前 Memo B 评为 99/100、修复后 Memo C 评为 100/100，两者均无硬失败。
- **结果：** 保留。提升仅为价格审计性 1 分，资本结论没有变化；不声称总体性能提升。

## Iteration 7：从单案例升级为三案例预注册对照

- **问题信号：** 单个 FermaDHA-X 场景只能证明一个供需/扩产工作流差异，容易被误读为通用优势。
- **假设：** 在不同风险结构下冻结输入、量表、匿名输出和盲评，可以更可靠地区分可重复优势与偶然措辞差异。
- **最小修改：** 增加 MycoPro-PV9 跨菌株/物种/法规案例和 DermaBis-A95 产品形态/内部经济性案例；先提交协议和 rubric，再生成输出和评分。
- **验证：** Direct 总分 283/300，Skill 298/300，平均差 +5.0；两组均无硬失败，三次 headline decision 相同。Case 2 差异实质，Case 3 差异轻微。
- **结果：** 保留三案例 benchmark，不新增 Skill 规则。剩余扣分对应的规则已经存在，继续补规则会过拟合合成量表；下一阶段转向真实证据包、人类专家和重复运行。

## Iteration 8：从结构化任务改为一句话、重复运行

- **问题信号：** 结构化提示已经把大部分专业框架告诉 Direct 组，无法证明普通用户只说一句话时 Skill 是否仍然完整；单次运行也无法支持“模型不稳定”的判断。
- **假设：** facts-only 输入、每案一句请求和每种条件三次独立会话，可以分开观察框架覆盖与运行波动。
- **最小修改：** 预注册一句话协议和解释门槛；保存 18 份匿名原始输出、盲评分、揭盲映射与机器可读数据，不修改 Skill 规则。
- **验证：** Skill 9 份输出均分 95.0、最低 87、总体标准差 4.7；Direct 均分 85.7、最低 60、总体标准差 11.4。Skill 在 3/3 案例中均分更高、组内极差与标准差更小；两组均无硬失败且 headline decision 相同。
- **反证：** Direct 在 FermaDHA-X 已很强；MycoPro 的合格可销售产能换算由 Skill 漏掉 2/3、Direct 漏掉 1/3；一份 Skill 输出存在十倍数字转录错误但未改变结论；评分前未预提交分组映射或承诺哈希，第三方不能独立排除重分组。
- **结果：** 保留当前 Skill 和评测，不为追分新增规则。公开结论限定为这些合成案例中的框架完整性和稳定性差异；在人类专家复核前不称“行业认可”。

## Repair policy

1. 先保存当前最佳版本、输入条件和已知限制；
2. 优先修复会导致错误推进的硬门槛；
3. 只做能关闭 evidence、coverage 或 decision gap 的最小修改；
4. 用同一场景复测，不移动评分标准；
5. 改善则保留，无改善则回退或继续定位；
6. 在案例和 README 中同步保留未解决问题。
